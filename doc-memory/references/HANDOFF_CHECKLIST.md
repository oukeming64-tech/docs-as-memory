# HANDOFF_CHECKLIST — 文档交接证据封口（Seal）

这份清单内置在 `doc-memory` 中。它用于检查“已经做完、文档也同步了”的声称，
不以作者摘要代替当前工作树和可复现结果。

## 1. 先立 claim

把完成声称拆成可验证的短句，例如：

- 哪些行为或接口已经实现；
- 哪些测试已经通过；
- 哪些文档已经同步；
- 哪些发布、数据迁移或人工验收仍不在本次范围。

## 2. 独立取证

- 查看当前文件与 diff，不移动、清理或覆盖审计对象；
- 运行与 claim 直接相关的测试或检查；
- 文档面只用 `overview` / `search` 定位最小集合；
- 运行 `python3 doc_memory.py validate`；
- 搜索与完成声称矛盾的 `todo / pending / next / blocked / known issue`，
  并人工判断语义，不能只凭关键词机械阻断。

## 3. 证据矩阵

| 面 | 证据要求 |
|---|---|
| Scope | 实际 diff 或明确文件范围 |
| Implementation | 当前实现路径、配置或运行行为 |
| Verification | 独立执行的测试/检查及结果 |
| Documentation | 实际读过的 shard 路径和 `validate` 输出 |
| Data | 数据、迁移或状态证据；确实不适用才写 N/A |
| Release | 是否已经发布；本地完成不能冒充上线 |
| Human acceptance | 需要人类视觉/产品判断时，必须明确是否已取得 |

`unknown` 不是 `N/A`。证据矩阵缺口必须写成未决项。

## 4. 输出顺序

1. 按严重度列 findings，并给出文件或命令证据；
2. 列未决问题；
3. 给出证据矩阵；
4. 记录实际运行的验证；
5. 明确结论：`PASS` 或 `BLOCKED`。

## 硬阻断

- `validate` 非 0 error 或索引过期；
- 完成声称只由作者摘要支持；
- 当前文档与 claim 明显冲突；
- 关键验证未运行却被写成通过；
- 把本地生成、候选、人工未验收或未发布状态写成正式交付。
